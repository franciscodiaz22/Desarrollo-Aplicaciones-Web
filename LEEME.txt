PARTE 2 de 4 — Autenticacion y sesiones (Requisito #3 de la Etapa 4)
=====================================================================

IMPORTANTE: esta parte se sube DESPUES de que alguien haya subido la
Parte 1 (Tailwind). Si tu compañero de la Parte 1 aun no ha hecho su
commit, coordina con el/ella antes de continuar.

Que trae este zip (reemplaza/agrega estos archivos):
- login.html (nuevo)
- login.js (nuevo)
- database.sql (agrega la tabla "usuarios")
- server.js (agrega sesiones, login/logout, protege Eliminar)
- app.js (agrega el bloque de sesion)
- Index.html (agrega la barra de sesion arriba)
- package.json y package-lock.json (agregan express-session y bcryptjs)

Que hace esta parte:
Login y Logout con sesiones del lado del servidor (express-session, el
equivalente en Node de session_start()/$_SESSION en PHP). Las
contraseñas NUNCA se guardan en texto plano: se comparan con bcryptjs
contra un hash guardado en la base de datos. Mientras no haya sesion
iniciada, el boton "Eliminar" (que ya existia en el backend desde
antes) queda bloqueado.

Pasos:
1. `git pull` (para tener el commit de la Parte 1 ya aplicado).
2. Copia todos los archivos de este zip a la raiz del proyecto,
   reemplazando lo que exista.
3. Ejecuta el script database.sql en tu MySQL local:
   mysql -u root -p < database.sql
   (o vuelve a crear la base si ya la tenias: DROP DATABASE dashboard_db; y corre el script de nuevo)
4. Corre `npm install` (instala express-session y bcryptjs).
5. Corre `npm start`, entra a http://localhost:3000/login.html y
   confirma que puedes iniciar sesion con:
     usuario: admin
     contraseña: Admin2026!
   y que aparece "Cerrar sesion" arriba a la derecha.
6. Sube tu commit:
   git add login.html login.js database.sql server.js app.js Index.html package.json package-lock.json
   git commit -m "Etapa 4.2: Autenticacion con sesiones de servidor (login/logout)"
   git push

Antes de subirlo, entiende que hiciste: agregaste express-session para
manejar la sesion del servidor, un middleware requireAuth que protege
rutas privadas, dos rutas nuevas (/api/login y /api/logout), una tabla
"usuarios" con contraseñas hasheadas, y en el frontend un
verificarSesion() que consulta /api/session al cargar la pagina. Debes
poder explicar esto en el video.
